## 1. Repository layout

The template (everything except `docs/design/`, ADR-0001) already fixes the top level. Product code lands in the places below; do not add new top-level directories without an ADR.

```
.
├── apps/
│   ├── api/                  Python 3.12, FastAPI; package `app` under src/ (uv_build, module-root src)
│   │   ├── src/app/          api/ db/ settings.py logging.py errors.py middleware.py (template)
│   │   │                     schema/ graph/ ingest/ worker/ agent/ evals/ mcp/ (product, per 06 §5)
│   │   └── tests/            unit at top level; integration/ needs FalkorDB; load/ script
│   └── web/                  Next.js App Router, TypeScript, Tailwind v4, pnpm
│       └── src/              app/ (routes) components/ (layout, ui) lib/ (api, env, site)
├── evals/                    questions.yaml, runs/<utc>/ (read-only mount into the worker only; 06 B8)
├── docs/
│   ├── design/               pre-event design notes and adr/ (not edited after CP0 except by ADR)
│   ├── product/              charter, PRD, TRD
│   ├── engineering/          this file
│   ├── DECISIONS.md          one ADR entry per decision
│   └── AI_USAGE.md           one row per AI-assisted PR (section 13)
├── .github/                  workflows/ci.yml, dependabot.yml, PULL_REQUEST_TEMPLATE.md
├── docker-compose.yml  .env.example  .pre-commit-config.yaml  README.md  LICENSE
```

- **ENG-01** One import direction in `apps/api`: `api` and `agent` and `mcp` depend on `graph`; `graph` depends on `db` and `schema`; nothing under `graph` imports `ingest` or `worker`. The reader client type exposes `ro_query` only (ADR 0005); the writer client type is importable only from `ingest/` and `worker/`. A unit test fails on a forbidden import (ADR 0016 "import-boundary rule").
- **ENG-02** Generated files (OpenAPI snapshot, TypeScript types generated from the `Answer` schema, `uv.lock`, `pnpm-lock.yaml`) are committed, never hand-edited, and regenerated by the command named in the `README.md` section "Development".
- **ENG-03** `evals/runs/<utc>/` is append-only. A frozen run is never rewritten; a re-run creates a new directory.

## 2. Branching and merging

Trunk-based, because the whole build is four days and the gates are CI (ADR 0016).

- **ENG-04** `main` is always deployable. Required checks on `main`: the CI jobs named in test-plan §5: `api-ci`, `web-ci`, `e2e-smoke`, `eval-tools-only`, `compose-up`, `images`, `secrets-scan`, `deps`, `docs`, `workflow-lint`, each required from the checkpoint stated there. The template's `ci.yml` jobs `api`, `web`, `compose` are renamed to `api-ci`, `web-ci`, `compose-up` at CP0 so the branch-protection names match. No direct pushes; squash merge only; linear history.
- **ENG-05** Branches are short-lived: open, review and merge within the same working block, target at most 4 hours and never past the next checkpoint (CP1 to CP8, `06-build-plan.md` §2.1). Name: `feat/<task-id>-<slug>` (team charter §4.1, `06` §3.1), for example `feat/GR-03-who-knows`. Task ids come from the task cards (`06` §5).
- **ENG-06** Unfinished work goes behind a settings flag (for example `EXTRACT_DECISIONS=false`, `KEPBRAIN_EMBEDDINGS_ENABLED=false`), not onto a long-lived branch. The flag default must leave `docker compose up` working without any key (CHR-SC-06).
- **ENG-07** Releases are tags on `main` as defined once in PRD §9.0: `v0.1-t03` at CP4, `v0.2-t01` at CP5, `v0.3-t02` at CP6 and `v1.0-submitted` at the Oct 18 17:30 freeze. No release branches. Hotfix during judging = a normal PR with the same gates.
- **ENG-08** No commit may carry an author or committer date before 2026-10-15 00:01 IST (PRD-G-07). Never rebase or amend commits already on `main`; never set `GIT_COMMITTER_DATE`/`--date`. Before the first push each day run `git log --since=... --format=%cI` and check the earliest timestamp.
- **ENG-09** Squash-merge commit = the PR title plus body; keep the Co-Authored-By trailer (section 3) in the squashed message. If the platform drops it, add it back in the merge dialog.

## 3. Commits

Conventional Commits 1.0, one logical change per commit, imperative mood, subject at most 72 characters.

```
<type>(<scope>): <subject>

<body: why, not what; reference the task card id and ADR numbers>

Co-Authored-By: <assistant name and model> <noreply@anthropic.com>
```

- **ENG-10** Types: `feat`, `fix`, `perf`, `refactor`, `test`, `docs`, `build`, `ci`, `chore`, `revert`. Scopes are the directories or task lanes: `api`, `web`, `graph`, `ingest`, `agent`, `mcp`, `evals`, `schema`, `infra`, `docs`, `adr`. Breaking changes use `!` and a `BREAKING CHANGE:` footer (relevant to the `Answer` schema and tool signatures, which are contracts: ADR 0009, ADR 0004).
- **ENG-11** **AI-assisted commit policy.** Any commit in which an AI assistant wrote or materially edited files carries a `Co-Authored-By:` trailer naming the assistant and model of that session; the model ids are taken from the session record in `docs/AI_USAGE.md` and are not restated here (CHR-OQ-13). The trailer is the commit-level disclosure; the `docs/AI_USAGE.md` row (section 13) is the PR-level disclosure. Both are required. A human who only reviewed or ran the code does not add the trailer; a human who edited the output substantially is the author and the assistant stays as co-author.
- **ENG-12** A commit that touches files and is made by an agent on a human's behalf is committed under that human's git identity (the account accountable for it in the explain-back, Rules 11-13); the trailer identifies the assistant. No agent has a separate GitHub account. **DECISION (veto-able):** alternative is a bot identity per agent; rejected because Rules 11-13 need a named human per change.
- **ENG-13** Commit messages never contain secrets, personal data from Kubernetes sources (e-mails, private URLs) or pasted comment dumps (ADR 0020).
- **ENG-14** Pre-commit hooks run on every commit (`uvx pre-commit install` once per clone): whitespace, EOF newline, LF endings, YAML/TOML/JSON validity, files over 1024 KB blocked, merge-conflict markers, private-key detection, `ruff-check --fix` and `ruff-format` on `apps/api/`, prettier on all other supported files. Never use `--no-verify`. `apps/web` is formatted by `pnpm format` and checked by CI.

## 4. Pull requests

- **ENG-15** Size: target under 400 changed lines excluding lockfiles and generated files; over 800 must be split unless it is a pure move or a generated snapshot. One task card per PR where possible.
- **ENG-16** Every PR uses `.github/PULL_REQUEST_TEMPLATE.md`: summary, changes, how to test (exact commands or clicks), and the checklist. The checklist is extended for this product by section 4.1.
- **ENG-17** Review: one approval from a team member who did not author the PR (an AI assistant does not count as the reviewer of record; automated review output is attached as a comment and its findings resolved or answered). With one person on the team, the author waits for CI, reads the diff top to bottom once as a reviewer, records that in the PR, and logs the review in `docs/AI_USAGE.md` under "Humans did". Never merge with a red required check.
- **ENG-18** Review turnaround target: 30 minutes during the event window; a PR waiting longer is raised with H-Lead.

### 4.1 Review checklist (added to the template's)

Reviewer ticks each item or writes "n/a" with a reason.

1. **Bounded Cypher.** Every variable-length path has an explicit upper bound (`*1..3`, never `*` or `*1..`); every `LIMIT` is a literal fixed per template variant; `SKIP`/`LIMIT` are never parameters; every query that can return many rows has a `LIMIT` and the tool returns a `truncated` flag (`03` §15, ≤ 200 rows per call).
2. **Parameters, not strings.** No f-string, `%` or `+` composition of Cypher with user, LLM or graph-derived text. Values go in `$params`. Labels and relationship types in a template are literals, or are chosen from the allowlist in `app/schema/allowlist.py`, never from input.
3. **LLM-reachable queries are read-only.** Anything reachable from the planner, `POST /v1/tools/*` or the MCP server runs through `ro_query(template, params, timeout=...)` as `kb_reader`; the template contains none of `CREATE`, `MERGE`, `SET`, `DELETE`, `REMOVE`, `DROP`, `CALL` of a write procedure (ADR 0004, 0005). No new tool is added without a catalog entry (name, parameters with bounds, template, result shape).
4. **Evidence on every answer path.** Every new or changed tool row carries `label` and `key`, so an `evidence_id` can be computed; every claim path in the agent cites evidence ids; no URL is built from LLM text; the deterministic validator still converts unsupported answers to abstentions (ADR 0009). A change that returns facts without evidence ids is rejected.
5. **Freshness and provenance.** Facts returned carry `source_sha`/`observed_at` or the relevant provenance property; `freshness` stays in the response.
6. **No secrets, no personal data.** No keys, tokens, passwords, `.env` values; no e-mail addresses, private lists or password-bearing meeting URLs in code, fixtures, snapshots, logs or docs (ADR 0020; PII scrub tests green).
7. **Writes are idempotent.** New ingestion writes use `MERGE` on the label's `key` (section 8), edges merged after endpoints are matched, `content_hash` guarded `ON MATCH SET`.
8. **Tests included** at the level required by the Definition of Done (section 5); a bug fix includes the test that failed before the fix.
9. **Contracts.** `Answer` schema, OpenAPI and generated TypeScript types updated and their snapshots regenerated in the same PR.
10. **Docs and ADR.** README rows (ports, env variables, commands) updated; an ADR added to `docs/DECISIONS.md` if a technical decision changed (`docs/DECISIONS.md` is where Rules 11-13 explanations are checked).
11. **AI-usage row** added (section 13) and the commit trailer present (ENG-11).
12. **Writes outside the sandbox.** Nothing posts to `kubernetes/*`, `kubernetes-sigs/*`, `kubernetes-client/*`, `kubernetes-csi/*` or `cncf/*`; actions target only the team's demo repository and require human confirmation (ADR 0021).

## 5. Definition of Done

A task is done only when every item for its type is true and its PR is merged to `main` with CI green. "Works on my machine" is not done.

| Task type | Done means |
|---|---|
| **All** | Review checklist (4.1) passed; CI green; AI-usage row and trailer present (if AI-assisted); no TODO without a task id; no commented-out code (ruff `ERA`); the task card's smoke test or exit evidence is recorded in the PR |
| **Graph schema / index / constraint** | Defined in `app/schema/` in code form matching `03` §4, §12, §13; applied idempotently by `schema apply`; integration test shows indexes and constraints reach `OPERATIONAL`; applying twice changes nothing |
| **Ingestion / parser** | Unit tests on fixture files, including the recon quality cases the card names (duplicate KEP numbers, casing of logins, missing fields); PII scrubber runs before hashing; fixture mini-repo ingested twice yields identical node and edge counts (integration); `SyncRun` records counts; G4 invariant scan reports zero hits |
| **Tool (query intent)** | Catalog entry complete; Pydantic parameter model with bounds; one fixed template; unit test of parameter validation; integration test against the fixture graph proving the right rows, `label`/`key` on rows, `truncated` behaviour, and timeout behaviour where relevant; tools-only eval subset question passes if the tool serves one; `EXPLAIN` or `PROFILE` output reviewed for the template and noted in the PR when it has more than one hop |
| **Agent / LLM** | Works against the recorded provider double without network; claim validator tests cover missing id, foreign URL, empty claims; abstention reasons asserted; no change to the `Answer` schema without snapshot update; token and turn budgets enforced and tested |
| **API endpoint** | Pydantic request and response models; OpenAPI snapshot updated; error responses use the shared error model; request id in logs; tests for success, validation failure and downstream unavailable (`graph_unavailable`) |
| **MCP / action** | Tool list matches the catalog; action tools require explicit human confirm; denylist test (ADR 0021) proves a refused target; dry-run output shown in the PR |
| **Web page / component** | Server component unless it needs interaction (ENG-33); loading, empty, error and degraded-LLM states built; keyboard-only walk and visible focus checked; contrast checked against tokens; vitest for logic-bearing components; Playwright judge-path smoke still passes; checked at 360 px and 1280 px widths |
| **Eval** | Question records carry `verified_at` and `verified_by`; grader unit-tested on at least one pass and one fail case; run output written under `evals/runs/<utc>/`; losses are reported, not filtered |
| **Infra / deploy** | `docker compose config --quiet` clean; every service has a healthcheck; no database port published; a restore or rollback step written in `docs/RUNBOOK.md` and run once; secrets only via `.env` or CI secrets |
| **Docs** | Links resolve (`docs` CI job); numbers carry their source, date and VERIFIED/INFERENCE/UNVERIFIED status where they come from outside the repo; formatted by prettier |
| **Dependency bump** | Section 11 followed; lockfile diff reviewed; all CI jobs green |

## 6. Python standards (`apps/api`)

The enforced configuration is `apps/api/pyproject.toml`; this section states what it means in practice and does not restate every rule.

- **ENG-19** Python `>=3.12,<3.13`, `uv` for everything (`uv sync --locked`, `uv run ...`). CI runs `ruff check .`, `ruff format --check .`, `mypy` (paths from `[tool.mypy] files`), `pytest`. Run the same four commands before pushing.
- **ENG-20** Ruff: line length 100; rule families selected in `[tool.ruff.lint]` include `S` (bandit), `ANN` (annotations), `T20` (no `print`), `DTZ` (timezone-aware datetimes), `TRY`, `LOG`/`G`, `PT`, `ERA`. Do not add file-wide `noqa`. A suppression is allowed only as a per-line `# noqa: CODE` with a reason, or as a `per-file-ignores` entry with a comment in `pyproject.toml`, as the existing `tests/**` and `src/app/db/falkordb.py` entries do. Adding a new global `ignore` needs an ADR.
- **ENG-21** mypy `strict = true`, `warn_unreachable`, plugin `pydantic.mypy`. Every function is fully annotated. `Any` only at the untyped `falkordb` boundary (`app/db/falkordb.py`); results from the client are validated into Pydantic models at that boundary, so `Any` does not travel. `# type: ignore` must carry an error code (`ignore-without-code` is enabled) and a reason.
- **ENG-22** Pydantic v2 models for every request, response, tool parameter set, settings and graph row. Use `extra="forbid"` for tool parameters and settings; use bounded types (`conint`, `constr`, `Annotated[..., Field(le=...)]`) so the bounds in the tool catalog are enforced by the model, not by prose. Settings come from `pydantic-settings`; nothing reads `os.environ` outside `settings.py`.
- **ENG-23** Logging: `structlog` JSON logs with request id; no `print`; never log secrets, prompts containing user text at INFO, or full Cypher parameters containing personal data. Log the tool name, template id, row count and duration.
- **ENG-24** Errors: raise typed exceptions from `errors.py`; map them to the shared error model at the edge; no bare `except`; no swallowing (`TRY`). The graph being unreachable maps to `graph_unavailable` and, on the ask path, to an abstention (ADR 0009), not a 500.
- **ENG-25** Time: timezone-aware UTC datetimes only (`DTZ`); store ISO-8601 UTC strings or epoch integers in the graph per `03` §7; convert to IST only in the web layer.
- **ENG-26** Async: FastAPI handlers and the planner are async; blocking calls (file I/O in parsers, CPU-bound hashing of large batches) run in the worker or `anyio.to_thread`. HTTP uses `httpx` at runtime; tests use the TestClient stack the template already configured (`httpx2`, see the comment in `pyproject.toml`).
- **ENG-27** Structure: functions short enough to read in one screen; pure parsing and scoring logic separated from I/O so it is unit-testable; no module-level side effects (no connections at import); dependency injection through FastAPI `Depends` and constructor arguments.
- **ENG-28** Comments say why, not what. Docstrings on public functions state units, bounds and failure behaviour. No author names or dates in comments.

## 7. TypeScript and React standards (`apps/web`)

Stack as pinned in `package.json`: Next.js 16 App Router, React 19, Tailwind 4, TypeScript 5.9, ESLint 10 with `eslint-config-next` and `eslint-config-prettier`, Prettier 3 with the Tailwind plugin, pnpm 12, Node 24.

- **ENG-29** Gates: `pnpm check` (= lint, typecheck with `next typegen && tsc --noEmit`, `format:check`) and `pnpm build` must pass before pushing. The directory `apps/web/AGENTS.md` instructs: read the relevant guide in `node_modules/next/dist/docs/` before using a Next.js API, because this version has breaking changes. Contributors and agents follow it; do not rely on memory of older Next.js.
- **ENG-30** `tsconfig` stays `strict: true`. No `any`, no non-null assertion `!` without a comment, no `@ts-ignore` (use `@ts-expect-error` with a reason, rarely). API responses are typed from the generated types for the `Answer` and tool schemas; runtime-validate data crossing the network boundary when it is not covered by the generated types.
- **ENG-31** Exports: named exports for components and utilities; default exports only where Next.js requires them (`page.tsx`, `layout.tsx`, `error.tsx`, `not-found.tsx`). File names kebab-case for non-component files, PascalCase components in kebab-case files (`answer-card.tsx` exports `AnswerCard`). **DECISION (veto-able):** alternative is PascalCase file names; chosen to match the template's existing `src/components/{layout,ui}` layout, so confirm against it on Oct 15.
- **ENG-32** Environment: public values only through `NEXT_PUBLIC_*`; the API URL for server code through `API_URL` read in `src/lib/env`; `server-only` is imported in modules that read server secrets or call the API with credentials so a client import is a build error.
- **ENG-33** **Server components by default.** A file gets `"use client"` only for interaction (event handlers, local state, effects, browser APIs, the graph canvas). Push the client boundary to the smallest leaf; pass serialisable props; fetch data in server components via `src/lib/api`, not in `useEffect`. Each client component is justified in one comment line if not obvious.
- **ENG-34** **Token-only styling.** Colours, spacing scale, radii, shadows, type sizes and motion durations come from design tokens defined once in `globals.css` (Tailwind 4 theme variables) per `05-ui-brief.md`. No hex, `rgb()`, `hsl()` or pixel literals in components; no arbitrary-value utilities such as `bg-[#...]` or `w-[413px]`; no inline `style` for visual properties (graph canvas geometry computed at runtime is the exception). Light and dark themes are both defined at the token level. A review grep for `#[0-9a-fA-F]{3,8}` in `src/` outside `globals.css` must be empty.
- **ENG-35** Accessibility, measured against WCAG 2.2 AA: semantic landmarks and headings in order; every interactive element reachable and operable by keyboard with a visible focus ring; buttons are `<button>`, links are `<a>`/`Link`; images and icons have text alternatives or are `aria-hidden`; form controls have labels; colour is never the only signal (abstention, stale, contradiction states also carry text or icons); contrast 4.5:1 for body text and 3:1 for large text and UI boundaries, checked on both themes; respects `prefers-reduced-motion`; async answer and error regions use `aria-live`; the graph view has a list or table alternative that exposes the same evidence. The Playwright smoke includes a keyboard-only pass of the judge path.
- **ENG-36** Evidence UI contract: every rendered claim links its evidence; every evidence link opens the GitHub source URL given by the API (never constructed in the browser); abstentions render as first-class states with the reason enum, not as errors (ADR 0009); the "Data as of" chip is on every page that shows graph data.
- **ENG-37** Performance: no client-side bundle growth without need (check the build output size line in the PR when adding a dependency); images through `next/image`; no layout shift on loading states.
- **ENG-38** Formatting is Prettier's; do not hand-format. Tailwind class order is sorted by the plugin.

## 8. Cypher conventions

Authoritative names and keys are in `03-graph-model.md` §1, §3, §4, §5; this section is the discipline for writing queries against them.

- **ENG-39** Naming: labels `PascalCase` (`KEP`, `PullRequest`); relationship types `UPPER_SNAKE` (`TARGETS`, `PRR_APPROVED`); properties `snake_case`; graph names lower-case (`kep`, `kep_next`, `ops`, `eval_baseline`), memory graphs `mem:<ULID>` validated against `^mem:[0-9A-Z]{26}$` before any `select_graph`. Direction reads left to right as in the graph-model tables. Names are defined once in `app/schema/{labels,edges,properties}.py`; templates reference those constants, and a unit test fails on a label or type in a template that is not in the allowlist.
- **ENG-40** Identity: every node has a unique `key` formatted per `03` §3.1 (examples: `SIG` = `sig-node`; `Person` = lower-cased login without `@`; `KEP` = `keps/<sig-dir>/<dir>`, not the KEP number; `Issue`/`PullRequest` = `<repo>#<number>`). `MERGE` is always on `(:Label {key: $key})` alone; other properties go in `ON CREATE SET` or a guarded `ON MATCH SET`.
- **ENG-41** Edge merge: match both endpoints first, then `MERGE` the edge in its own clause with the discriminating property from `03` §5 for multi-instance types (`TARGETS.stage`, `PRR_APPROVED.stage`, `MENTIONS.match_kind`). Never `MERGE` a whole path (creates duplicates when an element is missing, `03` §3.3).
- **ENG-42** Writes (worker only, `kb_writer`): `UNWIND $rows AS r` in batches of 500, `timeout = 30000`; `ON MATCH SET` only when `content_hash` differs; soft delete via `archived = true`/`archived_at`, state edges closed with `valid_to`, never deleted outside a rebuild.
- **ENG-43** Reads: one fixed template per tool (ADR 0004); `GRAPH.RO_QUERY` only; per-call `timeout` of 2000 ms for agent tools, 1000 ms for memory recall, 60000 ms only for worker analytics (ADR 0005); server limits `TIMEOUT_MAX`, `QUERY_MEM_CAPACITY` and `RESULTSET_SIZE` are not raised to make a slow query pass; fix the query.
- **ENG-44** Bounds: variable-length paths always `*lo..hi` with `hi` a literal at most 4 for traversals started from a keyed node, 3 where the start is a full-text match. One exception: `path_between` may use `max_len` up to 6 (TRD-TR-025), kept only if its p99 stays under the 2,000 ms query timeout when measured before CP4; otherwise it drops to 4 (TRD-SR-017, TST-156). `LIMIT` is a literal in the template (variants 5/10/20 etc. exist as separate templates; never a parameter) and sits as early as ordering allows. `LIMIT` does not stop eager operations in FalkorDB, so restrict the match first (indexed start node, then expand), not after. Cap per call is 200 rows with a `truncated` flag.
- **ENG-45** Start from an index: every query begins at a node found by `key`, a secondary range index in `03` §12.2, or a full-text index (`CALL db.idx.fulltext.queryNodes`). A label scan (`MATCH (n:Label)` with only a non-indexed filter) is rejected in review for any LLM-reachable query. Booleans such as `archived` are filtered after the keyed lookup, not used as the entry.
- **ENG-46** Indexes and constraints are created only through `schema apply` from `app/schema/indexes.py`/`constraints.py`, in the FalkorDB v4.22.0 syntax recorded in `03` §12.1. A new secondary index needs a named tool that uses it (the table in `03` §12.2 is the rule: each index "earns its place by a tool"). Integration tests assert status `OPERATIONAL`. No relationship indexes unless a profiled query justifies one.
- **ENG-47** Every returned row carries `label` and `key`; paths are returned as `[key, REL, key, ...]`; `archived` nodes are excluded unless `include_archived = true`; "current value" filters use the `valid_to` sentinel from `03` §7, not `IS NULL` ad hoc.
- **ENG-48** Algorithms (`algo.pageRank`, `algo.betweenness`, `algo.WCC`, `algo.labelPropagation`, `algo.SPpaths`) run only in the worker analytics step or `rank_people(refresh=true)` within its documented bound, write results to the properties listed in `03` §14, and are never called from a free-form path.
- **ENG-49** Style: keywords upper-case; one clause per line; aliases short and meaningful; parameters `$snake_case`; every template stored with an id, a docstring-style header (purpose, parameters, bounds, expected row shape) and exported verbatim into the README (Rule 10) by the registry exporter, so the README never hand-copies a query.
- **ENG-50** Free-form text-to-Cypher is not written, not tested and not shipped in the judged path (PRD-NG-03). Exploration against a dev graph in the FalkorDB Browser is fine and is not committed.

## 9. Testing conventions

Strategy and gates are ADR 0016; these are the day-to-day rules. The test plan document (`docs/product/`) assigns test ids (`TST-nnn`); name tests so the id appears in the docstring or the parametrised case id.

- **ENG-51** Pyramid: unit (no network, no database), integration (real FalkorDB v4.22.0 with a generated ACL file, marker `integration`, runs when `FALKORDB_HOST` is set, as in `pyproject.toml`), contract (OpenAPI and `Answer` snapshots), eval subset (tools only, no LLM), web (vitest for components, one Playwright judge-path smoke), load (`tests/load`, 50 users, 60 s). Database behaviours (read-only enforcement, idempotency, ACL separation, single-winner claims) are never tested with mocks.
- **ENG-52** pytest settings are binding: `--strict-markers --strict-config`, `asyncio_mode = "auto"`, `filterwarnings = ["error"]`. A new warning is fixed or explicitly filtered with a reason in the same PR; do not blanket-ignore.
- **ENG-53** Layout: `tests/test_<module>.py` mirrors `src/app/<module>.py`; integration in `tests/integration/`; fixtures in `conftest.py`; shared fixture data (the mini-repo of KEP files, OWNERS, `sigs.yaml` fragments) under `tests/fixtures/` and contains no real e-mail addresses, even from public files.
- **ENG-54** Names: `test_<unit>_<condition>_<expected>`; one behaviour per test; `pytest.mark.parametrize` with ids for table cases; no sleeps (use events or polling with a bound); no test order dependence; each integration test creates and drops its own graph name.
- **ENG-55** No live network in unit or integration tests: GitHub client behaviour via `respx`; the LLM via the recorded provider double (`app/agent/provider/recorded.py`). The real LLM runs only in `kepbrain eval` and a manually triggered job, within the spend cap (CHR-B-06).
- **ENG-56** Property tests (Hypothesis) for the PII scrubber, key normalisation and cursor arithmetic. A property that finds a counter-example is committed as an example test.
- **ENG-57** Bug fixes start with a failing test. Flaky tests are fixed or deleted within the block they appear; a retry decorator is not a fix.
- **ENG-58** Coverage is a signal, not a gate: do not chase a percentage; the gates are the behaviours listed in ADR 0016 and the Definition of Done. Test names double as the README "what we verified" list, so write them as sentences a judge can read.
- **ENG-59** The eval is a regression gate for releases (CHR-SC-12): results are compared to the frozen run with intervals; misses are written down, not tuned away. Tests never read `evals/questions.yaml` expected answers into the api container (06 B8).

## 10. Documentation conventions

- **ENG-60** Markdown, formatted by Prettier (hook), LF endings, one H1 per file. Mermaid for diagrams. No code, scripts or manifests inside `docs/` before the code window opens (Rule 8); after CP0, short command snippets are fine.
- **ENG-61** Every claim from outside the repository states its source, the date checked, and a status: VERIFIED (opened the source), INFERENCE (reasoned from verified facts), UNVERIFIED. Numbers about Kubernetes data carry the commit SHA and fetch time (CHR-C-09).
- **ENG-62** Link instead of duplicating: product documents point to `docs/design/*` sections by number. Graph names, labels and relationship types are written only as in `03-graph-model.md`.
- **ENG-63** Decisions: one entry per decision in `docs/DECISIONS.md` (ADR format of ADR-0001: context, decision, alternatives, consequences, veto-able flag). A PR that changes a technical decision edits the ADR in the same PR; superseded ADRs are marked, not deleted.
- **ENG-64** README sections required by Rule 10 and CHR-SC-06: video, live link, judge path, setup (`docker compose up`), graph data model diagram, Cypher templates and algorithms (generated from the registry), "Why a graph, not a vector database", evaluation (generated from `summary.json`), data statement (Rule 6, Apache-2.0 NOTICE, removal-request path), AI-assistance disclosure, who did what, provenance (template boundary), feedback on FalkorDB. Each is owned by a task card in `06` §5.7.
- **ENG-65** Environment variables, ports and commands are documented in the README in the same PR that changes them. Reserved-but-unused variables are listed as reserved, not as read (see the 2026-10-12 `AI_USAGE.md` entry for why).
- **ENG-66** Runbook: `docs/RUNBOOK.md` holds deploy, rollback, backup, restore, blue/green rebuild and key rotation steps, each with a "last rehearsed" date.
- **ENG-67** Writing style: plain, specific, no marketing language, no invented numbers; units on every number; IST for event times, UTC in data; dates ISO-8601.

## 11. Dependency policy

- **ENG-68** Exact pins. Python dependencies are `==` in `pyproject.toml` and locked by `uv.lock`; web dependencies are exact versions in `package.json` (no `^` or `~`) and locked by `pnpm-lock.yaml`. CI installs with `uv sync --locked` and `pnpm install --frozen-lockfile`; a PR that changes a manifest without its lockfile fails.
- **ENG-69** Versions are looked up on the day from the registry, not recalled, and versions less than two weeks old are avoided unless a fix is needed. Record any non-obvious choice in the PR.
- **ENG-70** One datastore: FalkorDB only (Rule 3, ADR 0006). A dependency that is a database, queue, cache server or search engine is rejected. A unit test scans manifests for forbidden packages (ADR 0016 "no second store").
- **ENG-71** FalkorDB image pinned to `v4.22.0` by tag and digest, as in CI and Compose (ADR 0002). Base images by tag; GitHub Actions pinned to a commit SHA with the release in a trailing comment (as in `ci.yml`). 6.x is evaluated only after the event.
- **ENG-72** Licences: only permissive or weak-copyleft licences compatible with the repository licence (MIT; the ingested Kubernetes data is Apache-2.0 with a `NOTICE`, data-governance §3.1). A new dependency with another licence needs an ADR line. Prefer the standard library and existing dependencies over a new package for something under about 50 lines.
- **ENG-73** Adding a dependency needs a one-line justification in the PR (what it does, why not existing code, maintenance status). Remove unused dependencies in the PR that makes them unused.
- **ENG-74** Dependabot (`.github/dependabot.yml`) PRs are batched and merged only at a quiet moment with all CI jobs green; no dependency upgrades in the final 24 hours before submission (after Oct 17 18:00 IST) except a security fix. **DECISION (veto-able):** alternative is freezing from Oct 17 12:00; chosen later to leave CP6 room.
- **ENG-75** Vendored code or copied snippets from outside carry source URL and licence in a comment and in the README provenance section.

## 12. Security hygiene

- **ENG-76** Secrets: only in `.env` (git-ignored) and CI secrets; `.env.example` has no real values and keeps provider keys absent by default (ADR-0003 "Secrets"). Defined-but-empty counts as unset. `detect-private-key` runs in pre-commit; `gitleaks` runs in CI (ADR 0016). A leaked secret is revoked first, then removed; history rewriting is not a remedy once pushed.
- **ENG-77** Credentials and limits: LLM key has the hard spend cap set before the first request (CHR-B-06); the GitHub token is a dedicated read-only fine-grained PAT, not a maintainer's; FalkorDB has a password and five ACL users (`default` admin hash only, `kb_reader`, `kb_memory`, `kb_writer`, `kb_ops`; TRD-SR-049, `06` C9) with no published database port; host ports 6379 and 5432 are never used (CHR-C-08).
- **ENG-78** Least privilege by process: api, agent and MCP connect as `kb_reader` (`+GRAPH.RO_QUERY +PING +CLIENT|SETINFO`); memory writes as `kb_memory` restricted to `mem:*`; `ActionDraft` state and spend counters as `kb_ops` restricted to `~ops`; ingestion and analytics as `kb_writer` in the worker only (ADR 0005). Tests prove each denial.
- **ENG-79** Personal data (Rule 6, ADR 0020): e-mail addresses, private lists and password-bearing meeting URLs are stripped before hashing and storage; the post-sync invariant scan must report zero hits; nothing login-gated is fetched; no comment dumps in the repository; identity is the public GitHub login.
- **ENG-80** Untrusted text: everything from Kubernetes sources (issue bodies, comments, README text) and every LLM output is untrusted. It is never executed, never interpolated into Cypher, never used to build a URL, and is passed to the LLM as clearly delimited data. Prompt-injection text in a comment must not change tool choice beyond the catalog or trigger an action; actions need human confirmation (ADR 0021).
- **ENG-81** Web: security headers and CSP set in `next.config.ts`; user-supplied text rendered as text, no `dangerouslySetInnerHTML` for source or LLM text (answer markdown is rendered through a sanitising renderer that allows only evidence-matching links); outbound links `rel="noopener noreferrer"`.
- **ENG-82** API: request size limits, per-memory-id rate limit (30 asks per 10 minutes, charter A5), no CORS (the web app proxies `/api/*` same-origin, TRD-SR-031, TRD-TR-052), no stack traces in responses, request ids in logs.
- **ENG-83** Hosting: firewall 22/80/443 only, SSH key only, Caddy terminates TLS, containers `restart: unless-stopped`, non-root users in images, nightly backup with 7-day retention (ADR 0017). Backups are test-restored once before submission.
- **ENG-84** Supply chain: lockfiles and SHA-pinned Actions (ENG-68, ENG-71); workflow `permissions: contents: read` by default, widened per job only when needed; no third-party action that is not pinned.

## 13. AI-usage logging procedure (`docs/AI_USAGE.md`, Rules 11-13)

Rules 11-13 as the charter records them (CHR-C-04). `FABLE_CONTEXT.md` §0 groups them and quotes no separate numbers, so the labels below name the obligations, not verified rule numbers: AI assistance is allowed and must be disclosed; the team must understand and be able to explain the graph model, queries, architecture and decisions; work that is entirely AI-generated may be rejected. This procedure produces the evidence for all three from the repository alone.

**What is logged.** One row per PR in which an AI assistant took part, in any way that affected the diff: writing or editing code, tests, queries, docs or configuration; looking up facts that drove a decision; running commands that produced the evidence cited; reviewing and proposing fixes. Autocomplete of a few tokens is the only exclusion. A PR with no AI involvement has no row and says so in the PR description ("AI: none").

**When.** In the same PR, before merge, never afterwards from memory. The row is written by the author at the time the work is done; the assistant may draft it, a human must read, correct and own it.

**Where.** The table under "Event period (2026-10-15 to 2026-10-18, IST)" in `docs/AI_USAGE.md`, appended at the bottom (append-only; do not rewrite earlier rows except to fix an error, and note the correction in a new row). The template period section is closed.

**Columns (as the file defines them).**

| Column | What to write | Test for a good entry |
|---|---|---|
| Date | IST date the work was done | Matches commit dates |
| Area | Files or component touched, plus the PR number and task card id | A reader can open the diff from it |
| AI did | Tool and model name; what it produced, looked up or ran, in specific terms (files, queries, sources opened) | Names the assistant and model, not "AI helped" |
| Humans did | Names or roles of the people; the decisions they made; what they reviewed line by line; what they changed or rejected; tests they ran by hand | Shows a human decision or a human correction, not only "reviewed" |
| Verified by | The exact commands or checks and their outcome (`uv run pytest`, `pnpm check`, a query run against the fixture graph, a click path) | Someone can repeat it |

**Procedure.**

1. Before starting a task, the assistant is told the task card id and the rules that apply (this file, the graph model naming, ADR 0004, 0005, 0009). Human decisions (what to build, which alternative) are made and written down before generation, not after; the PR description carries them.
2. While working, keep a running list of: decisions the human made, assistant output the human changed or rejected, and verification commands run.
3. At PR time, add the row, add the `Co-Authored-By` trailer to the commits (ENG-11), and tick the checklist line. The row's "Area" names the PR and task id.
4. The reviewer checks the row against the diff: does "AI did" match the files? does "Humans did" show real decisions? Is "Verified by" something the reviewer can repeat? A vague row blocks the merge like a failing test.
5. Findings from automated review passes are logged as their own rows when the fix is made, saying which finding, what changed and that the decision is not yet a human one if so (the template-period rows set the precedent).
6. Anything the assistant looked up that influenced a decision and is not obvious from the diff is recorded in `docs/DECISIONS.md` with source and date, and referenced from the row.

**Explain-back (Rules 11-13).** Each member must be able to explain the graph model, queries, architecture and decisions. Each PR therefore has an owner human who can answer for it. Before submission (Oct 18, before the form) a 45-minute explain-back session is held (CHR-SC-08, TEAM-WA-18): each member walks through the graph model diagram, two or three tool templates and their `EXPLAIN` output, the abstention path, and one ADR they did not author. Results (who, date, topics, gaps found and fixed) are recorded in `docs/AI_USAGE.md` under the event table as a short "Explain-back" subsection. A member who fails a topic gets it taught and re-asked the same day; the PRs that member authored are re-read by the other reviewer.

**Not entirely AI-generated (Rules 11-13).** The log must show human-made decisions in every area: the graph model choices, the tool catalog, the eval ground truth (`verified_by: human` on questions, HUM-03), the architecture and each ADR with a veto-able default. Eval ground truth and the abstention policy are never generated and accepted without a human re-checking against the source at the pinned SHA.

**Submission.** The README "AI-assistance disclosure" and "who did what" are generated by reading this log, not written separately, so they cannot disagree. Before CP8, H-Review runs a consistency check: every merged PR has a row or "AI: none"; every AI-trailer commit maps to a row; no row is empty in any column.
