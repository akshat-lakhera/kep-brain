# AI usage

AI coding assistants are used in this project to draft code and documentation under human direction. Humans set the design, decide the scope, review every change before it is committed, and run the tests. Facts shown to users come from the graph, not from model memory.

Every pull request adds a row to the table below.

| Date | Area | What the AI did | What the human checked |
|---|---|---|---|
| 2026-10-15 | Scaffold | Set up project layout, tooling configuration and settings on top of the generator output | Generator output was committed unmodified first; diffs and pinned versions were reviewed |
| 2026-10-15 | API core | Drafted settings, error envelope, request-id middleware, FalkorDB role pool and batch writer | Reviewed line by line; unit tests run, integration tests run against a local FalkorDB with a throwaway graph |
| 2026-10-15 | Infra and docs | Drafted Dockerfiles, CI workflow, `.env.example`, README and this log | Compared `.env.example` with `settings.py`; validated `docker compose config`; built the API image |
| 2026-10-15 | README | Rewrote the README from the code and the live API | File paths in the FalkorDB table were checked by grep; counts were read from `/v1/meta` and `/v1/findings`; claims that could not be verified were left out |
| 2026-10-16 | Review fixes and dependencies | Drafted the fixes for the code-review issues: shared helpers in place of repeated code, removal of unread settings and dead code, error envelopes for client errors, PageRank computed once at derive time, the evidence chain in place of the force graphs, and paging for long tables; the automated dependency update pull requests were merged | Each fix is its own commit with the matching test changes, reviewed as a diff before it was committed; the dependency bumps were merged from their pull requests |
| 2026-10-17 | Shortcuts, About, redesign | Drafted the keyboard shortcuts and their `?` dialog, the privacy, licence and accessibility notes on About, the grounding of process questions in the KEP documents, the release-window and search fixes, and the web redesign | Reviewed as diffs before commit; the `?` dialog and the About page read the shortcut list from one file (`src/lib/shortcuts.ts`) so the two cannot disagree; the About notes were checked against the settings and the memory store they describe |
| 2026-10-18 | Product document, landing page, findings | Drafted `kep_brain.md` and its ingest as a `Document` with `Section`s, the prompt scope for questions about the product, the landing page with product screenshots and the evidence diagram, the sitemap, robots, manifest and Open Graph metadata, the suggested-fix labels for tolerated conventions in the findings, the answer-cache replay for every caller, and this README refresh | Each product document sentence was checked against the code it describes and cites a README heading through its anchor marker; unit tests cover the product ingest and the fix labels (`test_ingest_product_doc.py`, `test_findings_lifecycle.py`); every README claim was read back against the working tree |
